# 充电热预测：数据获取与实验计划

日期：2026-10-05（新加坡时间）。依据 Journal 1 第2、4–5、9–10页及本次检索的作者、大学、NASA和软件官方资料。

核实边界：已核对公开数据描述、作者处理代码、下载入口和相关论文；没有下载并解析完整热数据，没有训练或测得实验指标。NASA原始压缩包的本地HEAD检查因域名解析失败，网页工具也未能读取压缩包；不能把入口存在写成文件下载验证成功。MATR平台为动态页面，本次未核实其中每个附件能否实际下载。

## 1. 项目承诺与推荐路线

Journal承诺：简化物理热模型 → 神经网络直接温度预测或残差学习 → 不同功率水平下对比 → 温度结果、误差分析、物理假设和报告。它没有定义预测哪个部件，也没有指定功率档位、采样间隔或样本规模；硬件级热测试、生产固件及认证级安全验证在范围之外。

**建议保留“充电设备功率模块/散热器温度”作为主线候选，争取真实日志；并行用公开数据验证处理和建模方法。** 如果日志不可得，采用明确标注的模块热仿真；若导师允许改为电池充电温度，可以采用公开快充电池数据作为真实测量基准。这两种对象必须在报告中分开，不能用电池温度证明充电器散热器或连接器温度预测有效。

| 路线 | 研究对象 | 与Journal关系 | 能作出的结论 |
|---|---|---|---|
| A：真实设备日志 | 充电模块/散热器/连接器中选定一个 | 最直接，但需确认测温位置与数据可得性 | 该设备和已覆盖工况的真实温度预测表现 |
| B：公开电池数据 | 充电过程电芯温度 | 可作方法验证或经导师认可的具体化范围 | 指定电芯/快充协议的温度预测，不能推广到整桩 |
| C：模块热仿真 | 简化充电模块/散热器 | 与模块热问题一致，但需认可仿真交付边界 | 设定参数和模型假设下的原型行为，不能宣称实测验证 |

建议10月7日前确认对象与主数据路线；这是交付范围的必要定义，不要求暂停其他准备工作。

## 2. 数据源与下载位置

### 2.1 NASA Li-ion Battery Aging：先跑通导入与物理/NN对照

- [官方字段说明](https://data.nasa.gov/dataset/li-ion-battery-aging-datasets)。
- [NASA官方仓库](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/)，找到第5项 Batteries。
- [官方仓库列出的原始ZIP](https://phm-datasets.s3.amazonaws.com/NASA/5.+Battery+Data+Set.zip)。
- 文档明确charge记录含Time、Voltage_measured、Current_measured、Temperature_measured、Current_charge、Voltage_charge，cycle含ambient_temperature及开始时间。
- 先检查包内说明，选择具有完整charge测量的3–4颗电池；常见B0005/B0006/B0007/B0018作为待检查候选，不能在打开包之前保证每个文件或协议均满足需求。
- 官方介绍多温度循环和不同放电电流，不等于已证明有多个独立快充电流设置。逐charge循环统计电流与协议后才能判断是否适合“留出充电功率工况”实验。
- 环境温度可能是cycle级设定值，不是连续环境传感器；必须标记该区别。
- 官方字段说明页当前没有直接资源附件，但NASA主仓库列出ZIP，不应因此说数据不存在；此次附件传输仍未验证成功。

**用途判断：** 字段较清楚，适合快速构建时序温度基准；如果充电协议基本固定，只能评价该协议及其功率变化，不能宣称覆盖多个快充档位。

### 2.2 Stanford / MIT / Toyota MATR：优先评估多快充协议

- [Stanford实验室数据入口](https://chuehlab.stanford.edu/datasets)，定位Severson et al. (2019) Early Cycle Life Prediction和Attia et al. (2020) Fast Charging Optimization。
- [MATR数据平台](https://data.matr.io/1/)，优先检查2019 cycle-life数据。
- [作者读取仓库](https://github.com/rdbraatz/data-driven-prediction-of-battery-cycle-life-before-capacity-degradation)。README确认cycle含时间、电流、电压和温度，descriptor含charging policy。
- 下载完整cycle级MAT文件；不要只拿每cycle的Tmax/Tavg/Tmin、summary或容量曲线。
- [作者Batch1处理代码](https://raw.githubusercontent.com/rdbraatz/data-driven-prediction-of-battery-cycle-life-before-capacity-degradation/master/BuildPkl_Batch1.ipynb)直接读取原始t/I/V/T及policy；代码中Batch1文件名为`2017-05-12_batchdata_updated_struct_errorcorrect.mat`，以平台实际附件为准。
- 第一轮可从一个batch内选择多个协议、每协议多颗cell；优先限制早期相近老化阶段，避免协议效应与老化混杂。随后再扩展跨cell和跨batch评价。
- 环境条件、温度传感器位置、时间单位与充电段划分需从附件说明核查，不能凭字段名假设。平台附件本次未下载；作者代码存在不等于附件下载已验证。
- 作者仓库说明只有数据处理代码公开，原论文建模代码有额外学术许可要求。我们的热模型独立实现，不依赖获取其寿命预测模型代码。

**用途判断：** 更适合检验不同快充协议下的电芯温度响应。小电芯的高C-rate不等于整桩高kW；C-rate、绝对电流、功率和设备尺度都要分别记录。

### 2.3 CALCE CX2_4：多环境温度补充，非首选快充数据

- [CALCE官方数据页](https://calce.umd.edu/data)，定位CX2 Battery → CX2-4。
- 官方明确CX2_4提供独立Temperature文件夹的热电偶记录；循环过程环境温度在25/35/45/55 °C间变化。
- 电测试日志和温度文件分开，必须核实时间同步、传感器位置及charge段覆盖。其他CALCE文件不能仅因有温度工况名称就假定含设备实测温度。
- 其协议变化主要不能直接等同多快充功率设置，作为环境温度泛化的备选更合适；链接存在，但此次未成功读取附件内容。

### 2.4 充电功率模块热仿真：与原项目更直接相关的参考

[Izquierdo Gómez等，2022，Data-Driven Thermal Modelling for Anomaly Detection in Electric Vehicle Charging Stations](https://arxiv.org/abs/2207.05431)使用功率损耗驱动热阻/热容模型，生成模块散热器温度并训练神经网络。这证明该类仿真路线有文献基础，但本次没有找到并验证作者原始仿真数据或代码附件，应独立实现并写明与论文的差别。

本项目可先模拟一个模块，不必复现全站拓扑或异常检测任务。参数来源分为设备资料、训练数据标定、明确假设三类，不把文献设备参数当Deye参数。

### 2.5 不作为温度标签的数据

- [KIT EV充电数据](https://zenodo.org/records/17866847)：有充电电量/功率及temperature文件，但该温度是环境温度；可供负载输入研究，不能作为模块、电池或连接器温度真值。
- PVOD和ERA5：服务光伏主线，气象温度不能代替充电设备温度。
- 只含充电开始/结束时间、kWh和峰值功率的session摘要：不足以训练连续温度响应。
- 只含电池容量/SOH/RUL的数据：不等于含充电温度时序。

## 3. 最小数据清单

以下是本项目建议的数据契约，不是Journal已规定的字段。内部数据无公开下载入口，由导师/团队提供；本次不发送外部请求或邮件。

| 字段 | 单位/形式 | 必要性与说明 |
|---|---|---|
| device_id / cell_id | 字符串 | 必需，区分个体 |
| session_id / cycle_id | 字符串 | 必需，独立运行分组 |
| time_s | 秒，相对批次开始 | 必需，原始时间与采样间隔也保留 |
| target_temperature | °C或K | 必需，标注电芯/散热器/壳体/接点及测温位置 |
| ambient_temperature | °C或K | 必需；实测或设定值分别标识 |
| current、voltage / measured_power | A、V、W | 至少有一组同步可解释的负载输入；记录测量位置和电流符号 |
| operation_state | charge/rest等 | 必需，避免混入放电、静置或EIS |
| initial_temperature | °C或K | 从每段开始测量取得，标定/rollout使用 |
| cooling_state | 风扇/流量/模式 | 模块强制冷却时重要；固定条件可用元数据表达 |
| charge_policy、setpoint | C-rate/A/W/模式 | 多工况比较需要，实际值和设定值分开 |
| soc、capacity、cycle_index | %、Ah、次数 | 电池路线重要，控制初始状态与老化混杂 |
| loss或效率信息 | W、比例 | 充电模块物理模型需要；无法实测时需有可解释估计 |
| sensor_metadata、geometry | 文档 | 物理假设、传感器位置/精度、设备类型、参数来源 |

**P=VI是电功率，不是全部转化的发热功率。** 充电模块优先用Pin-Pout或效率图估计损耗；电池简化热源可用I²Reff作近似，但不能把充入电池的全部VI当发热，也不能把该近似称为完整电化学热模型。

建议数据覆盖低/中/高至少3类负载、升温/功率转换/冷却过程，每类多次独立运行。样本数是否够取决于独立cell/session和热动态覆盖，不按窗口数量代替独立实验数量。现成数据不足时缩小结论范围，不自行补造标签。

这些热数据不必与PVOD的2019年时间或坐标一致；它们是独立主线，以同一设备内部信号同步为重点。

## 4. 建议实验协议

### 实验0：导入、质量与可用性审核

1. 保存原文件、README、来源、许可和SHA256；不同数据源分目录，不覆盖原件。
2. MATLAB非v7.3先考虑scipy.io，v7.3/HDF5使用h5py；最终导出统一结构及session元数据。
3. 按session检查时间单调性、重复、采样间隔、缺失、温度单位、电流符号和充电段。
4. 绘制每session的I/V/P/T/Tamb，确认温度与负载能同步解释。
5. 缺失目标温度不插值制造测试真值；不跨session或大缺口插值。
6. 温度、功率覆盖表形成后决定哪些泛化实验可做。

建议先用原始采样；若需要统一网格，按实际信号和记录间隔选择，例如不比原始有效采样更细的5或10秒。稀疏记录不能通过插值变成“高频实测”。

### 实验1：简化物理基线

建议从单节点热模型开始：

```text
Cth * dT/dt = Qloss - (T - Tamb) / Rth
```

Cth为有效热容(J/K)，Rth为热阻(K/W)，Qloss为损耗(W)。这是一项待验证的模型假设，不代表真实设备温度均匀。模块散热器采用损耗输入；电池路线需独立选择热源模型。电池集中热模型的参考见[PyBaMM官方热模型说明](https://docs.pybamm.org/en/v25.10.2/source/examples/notebooks/models/thermal-models.html)。

只用训练session拟合参数，约束参数为正；记录可辨识性。若热源未知，不保证可以分别识别所有物理参数，可先估计有效时间常数和输入增益并如实命名。预测从初始温度开始递推，不能每一步都拿未来实测温度重置后声称完成长时预测。

### 实验2：公平模型比较

| 模型 | 用途 |
|---|---|
| Temperature persistence | 当前温度作为未来温度，检验NN是否有实际增益 |
| RC物理模型 | 可解释基线 |
| Ridge或小MLP | 验证低复杂度数据模型 |
| GRU或LSTM（二选一） | 学习时序热响应，不必两个都做 |
| RC + NN残差 | 检验物理与数据结合是否有益 |

建议先用过去5分钟的可用I/V/T/Tamb和工况预测未来60秒温度；数据足够再加300秒。具体采样与窗口在数据检查后冻结。这些长度是项目建议，不是文献或Journal规定。

未来60秒负载若未知，所有模型只能使用历史负载与可用设定，或使用同一负载预测；若已知未来功率计划，单独作为“已知负载计划”实验，各模型获得相同信息。不允许物理模型看到未来真实功率、NN只看历史，或反之。

RC+残差只用训练数据产生训练残差；每种模型使用相同预测目标、切分、起点温度与输入可用性。调参只用验证集，scaler只fit训练集。

### 实验3：不同功率/协议工况

- 同cell/设备后期独立session：检验随时间变化的泛化。
- 完全留出cell/设备：检验个体迁移，不能窗口随机拆分后称为跨设备。
- 按完整charging policy留出：检验未见充电协议；若所有数据只有一个协议，明确该实验不可做。
- 环境温度留出：仅在有足够温度组时进行；恒温数据不支持此结论。
- 对低/中/高功率、升温/冷却、CC/CV分别报告误差。功率分档依据训练集定义，再固定到测试集。

协议与设备完全绑定时，留出协议也留出了设备，应称为联合泛化，不把误差归因于单一功率因素。老化阶段、初始SOC、冷却和环境会混杂，应控制或分层报告。

### 实验4：物理合理性与消融

- 去掉历史温度、环境温度或电输入，分别检验信息贡献。
- 模块静置散热趋势、损耗增加时的温升响应、参数敏感性；电池物理检查要根据电化学热源与环境条件单独定义，不强制所有电池状态满足简单单调规则。
- 测试集评价不因离群或高温而临时删样本；数据质量剔除规则预先冻结。
- 指标包括MAE/RMSE(°C)、P95绝对误差、峰值温度误差、分工况与分session误差。温度MAPE不作主指标，R²作为辅助。
- 有可追溯的设备阈值才评价阈值预警；任意阈值只能称演示值，不能称安全标准。

## 5. 无真实模块数据时的仿真备选

生成不同功率计划、环境、初温及冷却参数的独立场景，保存随机种子与参数。示例负载可采用模块额定功率的25%/50%/75%/100%，不直接指定未知设备的kW。构造恒定、阶跃、渐变和停机冷却；温度范围和参数取自明确设备资料或标注假设。

不能把同一个RC方程生成的温度再用于证明RC+NN优于该方程。在无噪声、同参数情况下RC应近乎精确，此实验只验证实现与代理近似。若研究模型偏差，可用两节点/非线性散热模拟器生成真值、单节点RC作基线，留出负载与参数场景，明确这是人为设定的结构差异。NN收益不等于真实设备收益。

仿真产物必须带simulation标记。正常与异常场景分开，异常检测属于可选扩展，不取代Journal要求的温度预测比较。
